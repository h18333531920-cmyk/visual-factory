# 案例库：设计分组、AI标签与搜索规划

日期：2026-10-10
版本：v3，加入单项目逐图识别实验及直接应用规则。
状态：可用于样本验证和实施拆分的规划稿；建议默认值仍需试点验证。本文不授权上线、数据库迁移、批量重新标注或新增付费服务。

## 1. 目标与核心原则

目前项目只识别一张代表图，导致其他设计的元素漏搜；如果搜索平铺全部物料，英阿语版本又会大量重复。

本方案采用“项目 → 设计组 → 物料版本”组织内容：分类浏览继续以项目为主，关键词搜索展示相关设计组，每组默认一张命中图，其他版本可展开。

必须同时成立的原则：

1. **分组减少展示重复，标签描述内容，两者独立。** 同组不能证明所有版本包含相同元素。
2. **不同设计不能因同项目而被隐藏。** 搜kiki时，同项目的kiki骑摩托、kiki吃汉堡应各自出现。
3. **标签保留来源。** 必须知道标签来自哪张图、人工还是AI、是否确认、对应哪个图片版本。
4. **未识别不等于不存在。** 可以给出待核验候选，但不能虚构准确命中。
5. **人工工作量必须下降。** 不把逐图打标变成逐组手工确认的新负担。
6. **修改范围明确且可追溯。** 分组、分类、语言和AI任务不能顺带覆盖项目标签。

### 已确认需求与建议的区分

用户已明确：平台、国家共用；元素需要覆盖不同物料；搜索不能只给项目代表图，也不能铺满重复的英阿版本。

用户进一步明确首个实验的操作方式：

- 项目弹窗右上角增加“一键识别”。
- 点击后对该项目的物料逐张识别，不再只识别项目封面。
- 平台、国家等项目固定标签展示在弹窗顶部，继续作用于整个项目。
- 点击右侧物料切换左侧大图时，底部同步显示当前这一张物料自己的AI元素标签。
- AI结果直接应用，不再经过“建议—逐个采纳”步骤。
- 第一批实验只处理选定项目，不自动扩展到全库。

本文提出的设计组、候选结果分层、自动分组范围及识别预算属于实现建议。试点可调整阈值和默认值，但不能破坏上述原则。

### 1.1 首个实验的产品行为

首个实验不要求先完成自动设计分组。它先验证逐图标签能否改善搜索，设计组和英阿语去重随后读取这些逐图结果。

实验采用逻辑副本：继续只读引用原项目和原图片，逐图AI标签、排除记录与任务状态写入带实验标识的独立表。它不复制图片文件，也不修改原项目tags；关闭实验即可回到原行为，避免真实文件副本被误删或占用额外存储。

1. 打开实验项目弹窗，顶部显示项目固定标签。
2. 有维护权限的用户点击右上角“一键识别”。
3. 系统为项目内每张可识别图片建立任务，并显示总数、完成、失败、跳过和取消状态。
4. 单张成功后，其AI标签直接写入该物料；单张失败保留该物料原数据，并允许重试失败项。
5. 点击右侧任意物料时，左侧大图与底部“当前物料标签”同步切换。
6. 搜索读取逐图标签；设计组功能完成后再将英阿语版本折叠展示。

“直接应用”表示没有采纳确认步骤，不表示AI标签和人工标签无法区分。系统内部仍须记录来源，界面允许人工添加、删除或排除错误标签。

## 2. 内容结构与标签作用范围

项目“科威特足球活动”可以包含：

- 设计组A：kiki骑摩托开机海报，含EN和AR两个物料版本。
- 设计组B：kiki吃汉堡开机海报，含EN和AR两个物料版本。
- 设计组C：纯摩托车banner，含EN和AR两个物料版本。

搜kiki时应展示A、B两个设计组，展开后才展示各自的语言版本。

| 信息 | 保存位置与作用范围 | 搜索含义 |
|---|---|---|
| 平台、国家 | 项目；关联继承，不逐图复制 | 限定项目范围，项目内物料都生效 |
| 项目名称、所有者、项目链接 | 项目 | 项目文本检索与业务归属 |
| 活动主题、业务策略 | 带明确作用范围：整个项目、指定设计组或指定物料 | 仅对声明的范围生效 |
| 画面元素，如kiki、摩托车 | 具体物料及其内容版本 | 描述这张图片的内容 |
| 语言、尺寸、物料类型 | 具体物料 | 限定具体版本 |
| 项目/设计组元素汇总 | 从成员派生，保留来源ID | 发现相关项目或组，不代表每张图都有该元素 |

“手动/AI”是来源；“项目/组/物料”是作用范围，不能混为两套分类。

### 2.1 活动和策略不能无条件继承

同一活动项目可能包含新人优惠、免运、买一送一三套物料。项目记录“涉及买一送一”，不能让免运海报成为买一送一的准确结果。

- 新建或编辑主题/策略时，明确选择“整个项目通用”或“仅指定设计组/物料”。
- 项目涉及的主题/策略汇总，与声明对整个项目生效的标签分开保存。
- 同标签可以作用于多个组，组内特殊版本可以有显式排除；计算时以更具体的范围为准，物料排除优先于上级继承。
- 新增组员可以继承明确的组级业务标签；这不授予它任何图片元素标签。
- 旧项目主题/策略保留原值，标记为旧项目信息，未确认作用范围前仅用于项目相关检索。
- 第一阶段不把“不同物料属于不同国家/平台”混进同一项目；如确有该需求，另行扩展或拆项目。

## 3. 设计分组：定义、自动化与纠错

### 3.1 第一阶段边界

优先处理同项目、同物料类型、同尺寸的英阿语版本。主体、素材和主要构图一致，允许因语言产生镜像、文字块移动等合理变化。

- 不跨项目分组，不根据同名项目自动切换归属。
- 同尺寸、同标签、同文件名都不能单独证明同设计。
- 开屏与banner、明显不同主体或构图，第一阶段分开。
- 横竖裁切、跨尺寸适配、GIF/视频与静态图先不自动混组。
- 组成员可以有少量元素差异，因此组内版本仍需保留独立标签证据。
- 分组只改变展示关系，所有原文件与记录保留。

### 3.2 分组证据与决策

| 情况 | 默认处理 | 对用户的要求 |
|---|---|---|
| 同项目内文件内容完全一致，且类型、访问权限等不冲突 | 可自动归组，支持撤销 | 不必逐项确认 |
| 英阿配对满足经过试点验证的视觉与元数据规则 | 可自动归组，保留来源和撤销入口 | 只需处理异常，不要求每组点确认 |
| 有相似线索，但主体差异或证据不足 | 提出候选，暂时独立展示 | 可选择处理，不阻断上传 |
| 明显不同设计、用户曾明确拆开 | 保持独立 | 不反复要求确认同一候选 |

候选信号包括语言后缀、文件名结构、类型、尺寸和画面相似度。应保留可能区分设计的编号，不能把所有数字删掉后强行合并。

模型声称“很相似”不能直接作为可靠概率。自动规则先在人工标注的样本上验证，通过后才扩大应用。

### 3.3 防止连锁误合并

A像B、B像C，不代表A和C相同。不得仅沿相似关系连线就把整批图并成一组。

- 新成员需满足组内整体一致性检查，并检查是否与已有成员存在明显主体冲突。
- 组内人工设置“这两张不能同组”的约束优先于自动计算。
- 自动分组有疑义时保留独立组，不靠挑一个“万能代表图”掩盖组内差异。

### 3.4 人工纠错与日常维护

- 提供移出本组、合并设计组、选择代表图、撤销分组操作。
- 人工确认的分组受到保护，模型升级不自动重排。
- 追加物料只处理新增成员及受影响关系；替换图片使其自动分组证据过期，必要时重新确认。
- 合并/拆分必须原子提交，不能让一个物料同时落到两个组或暂时失去归属。
- 没有可靠归组关系的物料作为单成员设计组，正常参与搜索。

## 4. 标签证据与任务状态分开管理

### 4.1 图片识别任务状态

任务状态包括：未安排、排队、执行中、成功、失败、已取消、结果过期。

成功只表示任务正常返回，不代表识别出了画面里的全部元素。没有返回kiki，不等于确认没有kiki。

### 4.2 每个标签的状态

| 来源/状态 | 说明 | 是否作为当前物料的内容依据 |
|---|---|---|
| 人工确认或人工添加 | 用户确认该物料含此元素 | 是，优先级最高 |
| 当前图片的AI标签 | AI直接分析该版本并自动应用 | 是；记录AI来源，仍可人工纠正 |
| 同组推定 | 另一成员命中，当前版本未核验 | 仅作为关联候选，不能当直接命中 |
| 人工排除 | 用户确认该元素识别错误 | 排除该物料上的同词AI标签及同组推定 |
| 过期证据 | 依据旧图片内容得出 | 不参与当前直接匹配，保留历史 |

每条证据记录preview_id、内容指纹、规范标签、来源和版本。任务成功状态不能覆盖标签的人工判定。普通弹窗不再提供“AI建议待采纳”流程，但内部来源与人工判定仍必须保留。

### 4.3 直接应用与重新识别规则

一键识别必须按物料独立提交和保存，不能先拼成项目标签再整组回写。

- 首次成功：新增这张图的AI来源标签。
- 重新识别成功：用新结果替换这张图上一轮仍由AI管理的标签集合。
- 人工添加或人工确认的标签保留；AI新结果不能删除它们。
- 人工排除过的标签不能被同一内容的重识别自动加回。
- 识别失败、取消、超时或结果格式异常：不修改这张图现有标签。
- 图片内容指纹变化：旧AI标签标为过期，新任务成功后再切换到新结果。
- 每张图的更新独立并带版本条件；一张失败不能回滚其他成功图片，也不能把整个项目tags覆盖为空。
- 同一次批量任务重复返回时保持幂等，不能重复增加标签或重复计数。

直接应用后的AI标签应提供删除和“标记错误”操作。删除只针对当前物料；若用户明确选择批量应用到其他版本，系统显示目标列表后再执行。

### 4.4 同组推定的使用边界

- 只从已确认或达到自动归组规则的组产生推定；待确认的分组候选不传播标签。
- 推定必须能追溯到提供直接证据的成员，不能推定再推定。
- 来源本身是AI标签时，候选也须保留这一来源，不升级成已确认内容。
- 人工对AR版本排除kiki后，即使EN有kiki，也不能继续推荐AR含kiki。
- 来源标签撤销、内容替换、成员移组时，相关推定及时失效。
- 人工“应用到这些版本”应记录操作时明确选中的物料集合；将来新增成员不自动获得已确认的元素标签。

## 5. 逐图识别如何支持语言版本去重

首个实验逐张识别。下面场景仍必须处理，因为任务可能在不同时间完成、失败或被取消：EN已识别有kiki，AR暂时尚未识别。

| 用户操作 | 展示规则 |
|---|---|
| 搜kiki，不限语言 | 该设计组出现，默认展示有直接证据的EN图；可进入AR版本 |
| 偏好阿语，但不强制语言 | 仍展示有证据的EN图，注明AR待核验；不能用未识别AR冒充命中封面 |
| 筛选“仅阿语”再搜kiki | 若AR无直接证据，它不进入直接命中；可在“同组待核验”中单独显示AR候选 |
| AR后续直接识别或人工确认有kiki | AR进入直接命中，结果与计数更新 |
| AR被人工确认没有kiki | 移除该AR候选；EN仍可匹配 |

“偏好语言”是排序偏好，“仅某语言”是硬筛选，必须是两种不同操作。

同组待核验候选不混入直接命中数量。没有直接结果时，明确显示“暂无已识别的阿语结果，还有N组待核验”，不把未知状态显示成确定不存在。

跨版本漏识别不能仅靠界面解决。AR需要重试成功或人工确认才能成为直接结果；不能让已完成的EN标签自动替代失败的AR结果。

## 6. 上传与识别调度

### 6.1 推荐流程

1. 上传并保存物料、语言、尺寸、类型和项目归属。
2. 文件上传成功后即可浏览，AI或分组失败不回滚已成功上传的作品。
3. 可自动判断的版本直接归组，其他候选保持独立，用户不必先完成所有分组。
4. 对项目内每张可支持的图片独立识别，结果绑定preview_id与内容指纹。
5. 内容完全相同的文件可以复用一次识别结果，但仍为每个preview_id保存独立、可纠正的标签关系。
6. 失败、取消和不支持的版本进入明确的待处理状态；用户可重试失败项，结果到达后增量更新搜索。

### 6.2 一键识别的弹窗交互

- 按钮放在项目弹窗右上角操作区，文案使用“一键识别”；运行中显示完成数/总数并提供取消后续任务的入口。
- 只有具备维护权限时可点击；权限由服务端校验，前端隐藏按钮不是安全边界。
- 开始前显示本次将处理的图片数、跳过的视频或不支持文件数，以及“会直接更新逐图AI标签”的说明。
- 任务运行期间仍可浏览项目和切换物料；关闭弹窗后任务可继续，重新打开能恢复进度。
- 当前物料状态明确显示：未识别、识别中、已完成、失败、已过期。不要用空标签区同时代表“未识别”和“识别后无标签”。
- 顶部固定标签和底部当前物料标签使用清楚的区块标题，不依赖颜色作为唯一差异。
- 底部只展示当前大图的逐图标签；项目级标签不重复塞进每张图的标签区。
- 失败项支持“重试失败项”，不要求重新跑完整项目。
- 识别过程中如果物料被删除或替换，旧任务结果不得写入其他记录。

### 6.3 成本与复用

- 内容完全相同、识别规则版本兼容时复用缓存；缓存关联保持在授权范围内，不因跨账号缓存泄露项目或图像。
- 相似图片复用分组关系，不直接复用“已确认存在某元素”的结论。
- 给首次识别、后台补齐、失败重试分别设预算和并发上限，避免一个100张项目无限展开任务。
- 达到预算上限后显示尚未覆盖的设计/版本数，允许后续继续；上传本身不被卡住。
- 搜索可以统计哪些未核验版本经常被需要，用于补识别排序；用户打字不会无限触发新AI调用。
- 改标题、国家不重新识图；替换图片只使相关内容结果过期。
- 模型、词表升级先试点，不触发全库无提示重跑。

### 6.4 词表与动图

- 确认过的同义词归到稳定tag_id，例如摩托/摩托车；用户仍可输入习惯用词。
- 新词进入候选流程；含义不同的词不能只因相似就合并，例如泛指卡通老虎不必然就是kiki。
- 第一阶段GIF/视频可选静帧识别，结果注明来自哪些帧。命中封面使用含该元素的证据帧，不随意换成无关首帧。
- 未分析的帧仍属未知，不承诺覆盖全片；多帧识别放在后续阶段。

## 7. 搜索词如何解释

### 7.1 第一阶段采用可解释的词表匹配

先支持规范词、已确认别名、常见中英文表达和项目名，不依赖模型偷偷改写用户条件。

- 中文按词表最长匹配，兼容没有空格的输入；未知部分保留为文本检索条件。
- 多词项目名、英文短语不能机械拆成无关单词；先尝试项目名/已知短语匹配。
- 可识别的国家、平台、类型转为对应条件；画面元素进入物料内容条件。
- 界面用简短条件摘要显示当前理解，用户可删除或更正；后台字段名不暴露给普通用户。
- 没被支持的复杂语句按文本搜索处理并说明，不宣称已理解任意自然语言。

### 7.2 歧义规则

例如“足球”既可能是活动主题，也可能是画面元素：

- 明确选择“足球活动”筛选，按活动主题处理。
- 单独搜索“足球”，直接物料结果优先找画面内容/该物料文本证据；足球主题项目可在项目相关结果里出现。
- 提供切换为主题条件的入口，不把主题项目里的所有图片都宣称为画面有足球。
- 规范同义词匹配视为同一词；更宽泛的语义扩展另外标注，排序低于直接条件匹配。
- 人工排除某元素后，默认元素搜索不能再拿文件名里的同词把它加回来；显式按文件名查找仍可找到该文件，但标明是文本匹配。

### 7.3 多条件规则

默认多个条件同时满足；“任一词匹配”是显式选项，不能因结果少而自动改成OR。

| 查询 | 含义 |
|---|---|
| 科威特 kiki | 项目国家为科威特，同一候选物料命中kiki |
| kiki 摩托车 | 同一物料同时有两个词的匹配证据，不能跨组员拼凑 |
| kiki + 开屏 + 仅AR | 同一AR开屏版本命中kiki，不能由EN提供标签、AR提供语言来拼成直接结果 |
| 买一送一 kiki | 同一物料处于明确的买一送一标签作用范围，且有kiki的内容证据 |
| 项目名称 | 查到项目相关结果，进入项目设计组，不声称每张图包含标题里的画面元素 |

硬筛选先共同约束同一个版本，再选择封面和按组折叠。不能分别找到满足语言/类型/元素的不同版本后拼成一个准确结果。

## 8. 搜索展示：分层匹配与去重

### 8.1 默认结果层次

| 结果层 | 依据 | 默认展示与计数 |
|---|---|---|
| 直接物料命中 | 当前版本的人工标签、自动应用的AI标签或文件名匹配 | 按设计组折叠；保留依据，文件名匹配不宣称画面已确认 |
| 同组待核验 | 同组其他版本有证据，目标版本未知 | 单独收起或排在直接结果之后；不计入直接命中数 |
| 项目相关 | 项目名、旧项目元素或未确认范围的业务标签 | 按项目展示相关入口，不给每张物料制造精确命中 |

自动应用的AI标签默认参与普通搜索，搜索依据中保留AI来源。人工确认优先，用户可切换“只看已确认”；进入此模式后，仅当前版本人工确认的内容标签可以满足元素条件，AI标签、文件名和同组推定不能替代元素确认，待核验结果默认收起，可显式展开。

同一设计组同时有直接结果和待核验候选时，仅在直接结果中占一个位置，组内展示其他候选。项目相关层按项目去重，已出现直接结果的项目只补相关说明，不再把它的全部设计组重复列一遍。

### 8.2 展示单位

- 分类浏览、没有关键词：项目卡片为主。
- 有关键词：直接物料命中以设计组为单位，多套相关设计都能出现。
- 只有国家/平台筛选而没有关键词时仍按项目浏览；输入国家作为搜索条件时可进入设计组搜索，入口与当前模式须清楚。
- 一组默认一张命中图，可切换英阿版本；同项目多个设计组各自展示。
- 一个项目命中很多组时分页或“展开更多”，提示剩余数量；不能回退成每项目只给一个代表组。

卡片应能看出：项目归属、物料类型、可用语言、总版本数、直接命中版本数和简短依据。未识别版本用“待核验”表达，不用“无相关内容”。

### 8.3 搜索封面和点击

1. 选出满足所有硬条件的物料版本。
2. 根据证据等级、软语言偏好、预览可用性和稳定顺序选本次组代表图。
3. 若该版本图片加载失败，优先换同样满足条件的版本；没有则显示加载失败与重试，不能换不相关图冒充。
4. 点击具体结果，打开对应project_id与preview_id；先显示本次命中组，可切换项目全部物料。
5. 返回时保留搜索条件、排序、分页和滚动位置。

临时搜索封面不覆盖项目默认封面。切换到未命中版本后，要保留其“同组其他版本”身份，不能沿用前一张图的命中标签。

## 9. 数据模型与防覆盖规则

### 9.1 建议的逻辑实体

| 实体 | 关键内容 |
|---|---|
| 项目 | 现有ID、共用平台/国家、业务信息 |
| 设计组及成员 | group_id、project_id、preview_id、代表图、分组依据、人工约束、revision |
| 业务标签作用范围 | tag_id、项目/组/物料范围、继承或排除、revision |
| 元素词表 | tag_id、规范名、中英文别名及版本 |
| 物料标签证据 | preview_id、内容指纹、tag_id、人工/AI来源、判定状态、revision |
| 识别任务 | 内容指纹、模型/提示词/词表版本、任务状态、重试和预算记录 |
| 操作历史 | 对象、操作者、前后差异、时间、理由、撤销关联 |

同组推定是带来源的派生结果，不写成其他图片的已确认标签。一物料第一阶段仅归一个设计组，默认可为单成员组。

### 9.2 服务端必须保证的写入规则

- 不使用整个项目tags数组承载新分组和逐图元素修改；增删关联按字段范围独立操作。
- 更新带revision或等效条件；冲突时重新读取并解决，不用旧快照整组覆盖。
- AI返回只替换同一物料、同一内容版本中仍由AI管理的标签，不能修改人工确认、人工排除、项目固定标签或人工分组。
- 任务结果必须匹配当前preview_id及内容指纹；图片替换后到达的旧结果只留历史。
- 对同一识别目标和版本设唯一任务键，超时重试不得产生重复结果或重复标签；供应商是否支持请求去重需核实，结果不明时不得无限重发导致重复消耗。
- 模型升级后的新建议仍受既有人工作用约束；新模型不是覆盖人工选择的理由。
- 修改物料类型、语言、排序不修改项目标签。分组变更重算推定和索引，不删除原始标签证据。
- 合并、拆分或移动组成员前，展示受影响的组级业务标签；提交时一并保存作用范围及操作历史，不能让“整理设计组”悄悄扩大免运或买一送一的适用范围。
- 服务端按现有账号权限校验操作范围；前端隐藏按钮不是权限校验。
- 标签、任务及历史表的访问范围与项目一致；未授权物料不能通过搜索数量、缓存或标签接口泄露。

### 9.3 并发场景

| 事件顺序 | 必须得到的结果 |
|---|---|
| AI执行中 → 人工排除kiki → AI返回kiki | 保留人工排除，新建议不生效 |
| 旧图任务执行中 → 替换图片 → 旧结果返回 | 旧结果不标到新图 |
| A、B同时编辑不同标签 | 保留两人的有效修改，不让后提交者抹掉前者 |
| 识别中 → 拆分设计组 | 识别结果落到原物料，组汇总按当前成员关系计算 |
| 来源成员被删除或移出 → 目标版本原有同组推定 | 推定失效，不能成为无来源的残留标签 |
| 人工排除后选择撤销 | 由显式撤销改变判定；AI重跑不能代替撤销 |

### 9.4 索引、分页和结果更新

服务端应先对同一物料组合条件，再按组聚合、排序、分页；不要求浏览器把全库下载后计算，也不能先分页原始物料再去重。

区分项目数、设计组数、直接命中版本数、待核验候选数。严格模式与普通模式分别计算，不能共享一个含糊的“素材数”。

分页游标包含排序值和唯一组ID，并绑定查询及索引版本。查询期间分组合并、标签更新或新识别完成时，提示有新结果，刷新后切换到新版本；不能仅靠group_id声称能防止所有重复/漏页。权限撤销或内容删除即时生效，不因沿用旧分页快照而继续暴露。

人工修正应立即在当前页面生效；后台索引延迟要有更新状态。下一次查询可选择等待当前修订进入索引，避免刚删掉错误标签又立刻搜到旧结果。

## 10. 老数据迁移与逐步启用

1. 先备份项目、物料、标签及关联，记录迁移批次和前后差异。
2. 保留现有ID和存储路径，不因分组重建项目或重新上传文件。
3. 老项目元素保留为项目相关证据，不复制到所有物料；老主题/策略需要确认作用范围。
4. 从独立物料组开始，小范围生成分组候选和新索引；新旧检索可对照验证。
5. 人工确认组和标签优先迁移，禁止用空选择、失败请求或旧任务覆盖。
6. 每批核对记录数、标签差异、权限和搜索样例，确认后才扩大范围。
7. 可关闭新搜索与自动分组，恢复原浏览入口；关闭功能不删除原物料或回滚用户后来编辑的数据。

目前代码中的canonicalCaseProjectSource使用同名和文件名子集判断，不能证明跨项目内容相同。新搜索应按真实project_id/preview_id打开，迁移阶段必须消除它对新流程的隐式重定向；确有重复项目另走用户确认后的独立处理。

## 11. 实施顺序与交付门槛

| 阶段 | 工作 | 进入下一阶段前的条件 |
|---|---|---|
| 0A：单项目逐图实验 | 选定一个现有项目，接入一键识别、逐图AI标签、当前图片标签展示及失败重试 | 能安全关闭实验；原项目标签不变；逐图结果可核对、纠错和搜索 |
| 0B：真实分组样本验证 | 从实验结果中选3—5个有代表性的项目，标注分组和常见搜索期望；评估配对方法和人工耗时 | 明确哪些能自动分、哪些必须分开；有初步成本和纠错统计 |
| 1：数据与人工闭环 | 标签分层、作用范围、手工分组/补标、操作历史、并发保护；小批内部检索验证 | 不依赖AI也能完成搜索—定位—纠错；权限和防覆盖用例通过 |
| 2：设计组搜索 | 多词解析、证据分层、语言硬筛选/软偏好、组级分页、准确封面 | 样本中不同设计可见、英阿版本可展开、跨图条件不拼凑 |
| 3：自动化试点 | 接入经过阶段0验证的自动配对、逐图识别调度、完全重复内容缓存、限流和异常队列 | 与原流程比较，重复减少且人工耗时未增加；未发现未纠正的错误折叠 |
| 4：分批扩展 | 旧库补齐、更多尺寸适配、多帧识别及语义扩展 | 达到事先选定的指标目标，能回退，并有持续抽检 |

阶段0A先验证用户明确提出的逐图识别闭环，不把自动分组强塞进第一次实验。阶段0B再验证自动分组是否可用，不能等数据层全部建完才发现每组都需要人工整理。3—5个项目用于发现规则问题；扩大前还需在未参与规则调整的新项目上验证，不能用调过参数的原样本代替独立验收。

## 12. 如何衡量是否真的变好

上线前记录旧方案基线，再对同一批任务比较。以下指标必须有数据，具体目标在阶段0后填写，不能预先虚报识别准确率。

| 指标 | 测量方法 | 用途 |
|---|---|---|
| 英阿重复展示量 | 固定搜索任务中，同一设计重复占用的结果位置数 | 判断去重是否有效 |
| 错误折叠比例 | 人工抽检自动组，统计混入不同设计的组数/抽检组数 | 控制把关联设计藏掉的风险 |
| 设计召回率 | 已标注应该命中的设计组中，实际能检索出的比例 | 判断是否仍漏不同设计 |
| 版本召回率 | 在指定语言/类型条件下，应命中版本中有直接依据并被检索出的比例 | 防止组级召回掩盖阿语漏搜 |
| 不相关结果比例 | 搜索结果中经人工判定不满足条件的比例，按人工标签/AI标签/文件名分别统计 | 定位错标签或错误解析 |
| 人工工作量 | 每项目确认/拆组/补标操作次数及实际用时，与原流程及逐图方式比较 | 防止把工作转移给用户 |
| 识别成本与等待 | 每项目调用次数、重试量、费用或额度、首批可搜时间和补齐耗时 | 设置实际预算 |
| 覆盖程度 | 未识别物料数、已识别版本数、尚有内容差异的待处理版本 | 不能只报“代表图完成100%” |

试点必须纠正已发现的误折叠并查明原因后才扩展；样本没有误折叠不等于真实环境永远不会误分。持续保留抽检、撤销与用户反馈入口。

## 13. 必测场景

| 场景 | 验收预期 |
|---|---|
| 同项目两套不同kiki设计，各有英阿语 | 默认两组结果，每组版本可展开 |
| EN有kiki证据，AR未识别 | 无语言限制时EN命中；仅AR时进入待核验层，不虚报直接命中 |
| EN有kiki，AR人工排除kiki | AR不在默认元素搜索中命中或成为同组候选；显式文件名检索另按文本匹配说明 |
| 图A摩托车、图Bkiki | 双元素条件不跨图拼凑 |
| EN满足元素、AR满足语言筛选 | 两个版本不拼成同一直接命中 |
| 项目包含免运和买一送一两组 | 买一送一限定组，不让免运组继承该策略命中 |
| 搜足球，项目只有足球活动主题 | 作为项目相关呈现，不宣称每图都有足球 |
| A像B、B像C，A与C主体不同 | 不连锁合并成一个设计组 |
| 同尺寸、同文件名但画面不同 | 保持可区分；标题或文件名不能作为唯一去重依据 |
| AI结果晚到或重复返回 | 不覆盖人工判定、不污染新图片、不重复计数 |
| 人工分组后追加新物料 | 旧组不被打散，不给新成员自动复制已确认元素 |
| 搜索期间改标签或合并组 | 当前分页可解释，新结果提示刷新，不静默乱页 |
| 封面加载失败 | 不以不满足搜索条件的版本冒充 |
| 用户无项目权限 | 搜索预览、结果数、缓存及历史均不泄露该项目 |
| 修改类型/语言、识别失败 | 原项目标签完整保留 |
| 老项目仅有项目级元素 | 仍可通过项目相关入口找到，不伪造逐图证据 |
| 只在动图某帧出现元素 | 命中关联证据帧，不宣称其他帧都包含 |
| 一键识别只成功20/28张 | 20张直接应用；8张原数据保留并列入失败重试，不清空项目或物料标签 |
| 重识别返回不同标签 | 只替换AI管理部分，人工补充与排除保持不变 |
| 快速切换右侧缩略图 | 左侧大图、底部标签和识别状态始终属于同一个preview_id，不显示上一张残留 |

## 14. 当前建议默认值与待定项

以下是v2建议，不代表已批准开发或上线：

- 第一阶段自动配对以同项目、同类型、同尺寸英阿版本为主，跨尺寸适配以后扩展。
- 不要求用户逐组确认；试点验证过的规则可自动归组，疑难项独立显示并可处理。
- 自动应用的AI标签参与普通搜索，但与人工确认有来源区别；“只看已确认”提供更严格结果。
- 同组推定单独列为待核验；未识别AR不会冒充准确命中，也不会完全没有发现入口。
- 首次语言偏好建议跟随当前界面语言；没有对应物料语言偏好时用稳定的组默认顺序。硬筛选始终高于偏好。
- 保留项目分类浏览；关键词搜索按设计组展示；项目相关结果不重新铺开所有版本。
- 自动分组阈值、首批识别预算、后台并发/重试上限、结果页大小、验收数值目标待样本实测确定。

首个实验候选为 `AugPicks campaign (8.27-8.31)`。2026-09-30的只读快照显示该项目有28条物料记录；开工前重新读取当前数据库确认项目ID、图片数量和支持格式。实验仅对该项目启用，其他项目和现有搜索保持原状。

下一步先完成阶段0A的一键逐图识别闭环，核对标签质量、调用量、失败重试和搜索改善，再进入设计分组实验。
