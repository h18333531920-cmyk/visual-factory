## 账号权限与安全同步（2026-09-16 起）

- 金刚账号（icons 组）登录主站只能使用「制作金刚」和「团队管理」；admin 组使用静态 DIY 与素材库。权限由账号系统在服务端逐请求校验，前端隐藏只是体验，不是安全边界。
- 账号数据在生产权限库（Cloudflare D1）+ Supabase 行级安全（只约束新建受管账号，老账号不受影响）。账号增删在团队管理面板操作；测试站与生产共用 Supabase 认证，改动两边同时生效。
- 供应商会话只存服务器。浏览器扩展「GCC Design · 即梦本机桥」（0.2.0）由维护者导入管理员同步配置后，自动把即梦新登录态推送到服务器；新会话先过供应商活性校验，旧会话自动备份。网页和普通用户接触不到会话与同步配置。

### 常见维护场景

1. 生图报「会话过期 / siteSessionExpired」：维护者在自己电脑的浏览器重新登录即梦，打开扩展弹窗点「立即安全同步」（已配置时每 30 分钟自动同步）。无需登录服务器。
2. 同步配置丢失或需要轮换：按私有维护手册的轮换流程生成新令牌并在扩展重新导入，旧令牌立即失效，无需重启服务。
3. 账号权限或登录异常：先在团队管理面板查账号组与状态，再查服务器侧权限日志；普通账号问题不涉及服务器。

### 接手交接清单（新维护者向网站所有者索取）

1. 主站仓库工作区访问（工作区有大量未提交改动，禁止用旧 git HEAD 覆盖）。
2. 私有维护文档：`services/account-access/MAINTENANCE.md`（账号权限与服务器交接总记录）、`services/account-access/ROLLBACK-RUNBOOK.md`（回滚手册）、`services/icon-cutout/AI-API-OPS.md`（服务器实例与操作细节）。含服务器地址与路径，只走私下渠道，不入公开仓库或公开页面。
3. 服务器 SSH 公钥授权（由网站所有者添加）。
4. 扩展管理员同步配置文件（仅维护者持有，0600 私存）。

## 如何换服务

1. 先区分：更新过期登录态、同供应商换密钥、换模型，还是更换整个供应商。
2. 更新现有密钥或登录态，使用私有维护流程；网页设置页不写入或显示这些值。不要恢复旧的公开凭证分发、硬编码同步口令或向网页传 Cookie 的方式。
3. 换模型/供应商，核对其官方协议、参考图、返回格式、费用与异步任务行为，修改服务端适配器，保留“先记任务、只提交一次、恢复只查询”的规则。
4. 先检查服务是否可达、配置是否齐全，再使用未命中旧缓存的小样。检查通过或命中旧图片，不能证明新凭证能实际生图。
5. 多人共用账号意味着共享服务容量、无法准确按人审计，不代表必须把供应商凭证交给所有人。
6. 保留回滚代码和私有配置备份；不要清理任务收据来强制重试结果不明的请求。

## 测试与发布

- 先读取实际线上版本、git status 和当前工作区；历史 Git HEAD 与线上代码可能不一致，不要 reset/clean 或直接用旧代码覆盖。
- 工具运行 npm test、npm run build:site；主站运行 npm run build:pages、语法检查与 git diff --check。
- 验证金刚及静态 DIY 的真实生成、参考图、批量、断线恢复和结果导入。下载以实际文件或用户确认作为证据。
- 联调使用固定测试域名；随机部署地址不一定在登录/跨域允许范围内。
- 每次前端发布同时更新主站三处版本引用。使用测试分支发布，不要为了同步代码顺手 push main。
- Pages 发布和服务器容器发布是两件事。先完成测试，再安排正式切换；如需用户刷新网页、重新登录或更新同步扩展，要提前说明。
- 旧公开凭证分发、旧同步客户端和旧预览部署已于 2026-09-16 随正式版 v561 一并封堵（旧接口返回 410）。此前部署的版本不具备该结论；任何「网站已安全」的说法必须以当时的线上核对为准。
